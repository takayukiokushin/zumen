# 対応している端末（画面の大きさ）

2026-10-30 に、実際の画面で確認した結果。

| 端末 | 画面の幅の目安 | 使い心地 |
|---|---|---|
| **パソコン** | 1280px 以上 | すべての機能を、いちばん使いやすい形で使える |
| **タブレット**（縦・横） | 820〜1180px | **パソコンと同じ機能を、ほぼ同じ形で使える。** 図面の記号の移動・結線・拡大縮小（2本指）も、指でできる |
| **スマホ**（縦・横） | 390〜844px | 見る・入力する・声やスケッチから作る・保存・印刷は、使いやすい。図面の細かい編集は、できるが、小さい画面なので補助的な使い方を想定 |

モバイル専用の画面は作らない（決定。いまのまま）。同じ画面が、画面の幅に合わせて表示される。オフライン（通信なし）での利用にも対応しない（決定）。

## スマホで、見た目が変わるところ

- 上の帯は3段になる（名前／4つのタブ／右側のボタン）
- 図面一覧・消した案件・利用者の一覧は、1人（1件）を1枚のカードで表示する
- 「設備を入力して作成」は、入力欄が全幅の1列。「いまの構成」と「目次」は、ボタンで開く
- 図面の画面は、よく使うボタンだけを表に出す。ほかは「ほかの操作」、記号の一覧と選んだものの設定は「記号・設定」を押すと出る

## 指で図面を見る・動かす（タブレット・スマホ）

- 2本指でつまむ・広げる：縮小・拡大
- 2本指でなぞる、または、記号のない所を1本指でなぞる：画面を動かす
- 記号を1本指で動かす途中に、2本目の指を置く：動かしかけた記号は元に戻る（確定しない）
- ボタンや入力欄は、指で押す端末では、高さ44px以上

## 図面の「編集を開始」「編集を終了」（指で操作する端末だけ）

- **スマホ・タブレット（指で操作する端末）では、図面タブを開いた直後は「見るだけ」。** 帯には、「編集を開始」「（ほかの操作）」「縮小・拡大」だけが出る。記号の移動・追加・削除、線、結線、文字、「操作を戻す・進める」、右の「記号を追加・差し替え」、「結線を整える」「レイアウトの縮小・拡大」、レイヤーの追加・名前の変更・削除は、できない（レイヤーを選んで見ること、印刷プレビュー、印刷は、できる）
- 見るだけのあいだも、2本指の拡大縮小、なぞって画面を動かすことはできる（記号の上から始めても、画面が動くだけで、記号は動かない）
- 「編集を開始」を押すと、**同じボタンが、同じ位置で「編集を終了」に変わり**、今までどおりの編集ができる（「図面を編集中」の文字は、出さない）。編集中は、**図面を表示するエリアの外枠が、明るいオレンジ色の線（太さ4px）で囲まれ、色が、7秒かけて、ゆっくり流れる**（「動きを減らす」の設定の端末では、動かさず、静止した枠）。印刷プレビュー中は、編集できないので、枠は出ない。「編集を終了」で見るだけに戻り、枠も消える（保存はしない。保存は、これまでどおり「保存」のボタン）
- 図面タブを開き直すたび、別の案件を開くたびに、見るだけから始まる（図面が白紙のときも）。別の案件へ移る・ログアウトのときに、編集中かどうかの確認は出さず、いつもの「保存していません」の確認だけ
- パソコン（マウスのある端末）は、このボタンは出ず、いつも編集できる

## 使える高さが小さいとき（スマホの横向き・高さの小さい窓・大きい倍率）

- 「使える高さ ＝ 画面の高さ ÷ 画面全体の倍率」が640px以下のとき（html の `data-short="on"`。端末の種類は問わない）、上の帯をコンパクトにする（第17弾 項目7の調査4）。
  - 4つのタブは、必ず1行（名前は、足りなければ、その中で折り返す）
  - 「使い方・設定・利用者の管理・ログアウト」の行は、最初は畳む。「▼ 使い方・設定などを出す」で開く（開いた状態は、覚えない）
  - 実効幅が700pxより広いときは、「目次を出す」「いまの構成を出す」を、入力欄の見出しの行（「設備の入力」の横）に移す
  - 例：高さ800pxの窓で160%にすると、入力欄が、見える高さの20%（166px）から、52%（420px）になる（帯は98%から48%へ）。130%でも、44%から32%
- 実効幅が700px以下の狭い画面でも、使える高さが640px以下なら、右側の行は、最初は畳む（それ以外は、前回の開閉を覚える）
- 高さ500px以下のとき、サーバーの状態の知らせは、高さの34%まで（超える分は、知らせの中でなぞる）
- 横向きは、縦向きより、図面の見える範囲がせまい（高さ390pxのうち、上の帯と案件の行で、約半分）。図面を見る・直すときは、縦向きをおすすめする

## 確認のしかた（開発する人）

ブラウザの開発者向け画面ではなく、`playwright` で、幅 390 / 844 / 820 / 1180 / 1280 / 1440 の6通りを開き、
全画面の「画面の外に出た部品」「必要な幅」「小さい操作部品」を測った。実際のタブレット・スマホでの確認は、これからお願いする
（指の太さや、画面の叩き方による違いは、実機で確かめるのが確実）。

**常設の検査：** `pnpm screens`（ふつうの版。約14通り・約2分。先に `pnpm build`）と、`pnpm fuzz` の中の大きい版（約63通り・約500画面）が、
機器（スマホ縦・小さいスマホ・タブレット縦・横・パソコン）× 画面全体の大きさ（60〜160%）× 言語（5か国語）× 明るさ（明・暗）で、
全画面（ログイン・一覧・4つのタブ・設定・使い方）の、「横にはみ出す」「指で押す端末で44px未満」「文字が切れる」「画面の中のエラー」を調べる。
ブラウザを動かす道具（Playwright）が無い端末では、飛ばす（失敗にしない）。`scripts/check-screens.ts`

## スマホでの「画面全体の大きさ」の上限

- 設定の「画面全体の大きさ」は、パソコン・タブレットでは60〜160%。**スマホ（画面の実際の幅が700px以下、または、指で操作する端末で短いほうの辺が500px以下）では、130%まで**。160%にすると、上のタブなどが並びきらなくなるため。
- すでに160%に決めてある端末でも、スマホの大きさの画面では、130%として表示する（保存してある値は、書き換えない）。「文字の大きさ」は、どの端末も160%まで。
- 実装：`apps/web/src/settings/settings.tsx` の `PHONE_UI_MAX`・`isPhoneSized`・`effectiveUiScale`。
