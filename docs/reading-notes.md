# 読み取りのメモ（スケッチ・旧様式の PDF から、図面を作るときの決まりごと）

AI（スケッチ読み取り・音声入力）が判断するときの手がかりを、決まったものから順に残す。
**ここに書いたことのうち、AI が使うものは、指示文（`packages/ai/src/prompt.ts` の `DOMAIN_RULES`、
`packages/knowledge/src/ai-hints.ts`）に入っている。** このメモは、なぜそう決めたかの記録。

お客様の名前や図面そのものは、このリポジトリに入れない（リポジトリが公開のあいだは、とくに）。

## 役割は2つ

1. **スケッチ 1枚 → 新様式の図面**（現場で撮った手書きの写真から、図面を作る）
2. **旧様式の PDF 1枚 → 新様式の図面**（以前の図面を、新しい様式に直す）

どちらも、読み取った結果は、**必ず人が確認する画面**を通す。

## 決まったこと（2026-11-03、利用者の指示）

| 項目 | 決まり |
|---|---|
| 太陽光発電設備があるとき | **ZPD と OVGR は、セットで必ず必要。** スケッチに書かれていなくても、「あり」にする（理由：太陽光があるので必須）。太陽光が無いときは、書かれているときだけ「あり」 |
| RPR（逆電力継電器） | 太陽光があるとき、**現場によって必要かどうかが変わる。** スケッチに書かれていなければ、推測せず、**質問で確認する** |
| ZPD・OVGR・RPR のように、図から読み取れない機器 | **質問で確認する**（太陽光のときの ZPD・OVGR だけは、読み取れなくても「あり」） |
| 中電柱の名前 | **書いてある文字のまま。** 漢字で書いてあれば漢字、カタカナならカタカナ。互いに変換しない（直すのは人） |
| ケーブルの構造（CV・CVT） | **図に書いてある文字のまま。** ほかの資料と食い違っていても、補正しない。食い違いに気づいたら、メモ（notes）に書く |
| 変圧器の用途の書き方 | 「カ」「力」「動」「カTr」→ **動力**。「電」「灯」「電Tr」「灯Tr」→ **電灯**。人によって書き方が違う。読めないときは、質問か「自信なし」にする |

## 使っている見本（サンプル案件）で、分かっていること

見本（アプリで作った完成形）・旧様式の PDF・スケッチ4枚の、見比べの記録。
**これは、正解表（点数をつける試験）を作るときの注意であって、AI への指示ではない。**

- **鉛筆のスケッチは、300kVA の変圧器を4台描いているが、間違い。正しくは3台**（ほかのスケッチと見本は3台）。
  → 正解表では、3台を正解にする。AI が4台と読んでも、図に描いてあるとおりなので、AI の読み間違いとは数えない。
- **旧様式の PDF のケーブルは「CV」だが、今回の案件に限って、誤り。正しくは「CVT」**（設備の改修で、CV から CVT に変わった）。
  → ほかの案件では、旧様式の文字をそのまま使う。今回の案件の正解表だけ、CVT にする。
- スケッチの PCS の容量は、「450kW」「495kW」に見えるものがあるが、正しくは「45.0kW」「4.95kW」（小数点の見落とし）。
  → AI が、変圧器の容量（50kVA・200kVA）より大きい PCS を、そのまま答えず、確認できるようにする。
- 見本にあって、スケッチにも旧様式にも無いもの：ZPD・OVGR・RPR、「VT＋PF×2 V結線」「CT×2」、LBS の「40kA」。
  ZPD・OVGR は、太陽光があるので必須。RPR は、質問で確認する。ほかは、質問で確認する。
- スケッチの書き方：「DG」（DGR の略と思われる）、「太陽」「太陽光」（PCS と PV）、「CUT」（CVT と思われる）、
  「QB」（キュービクルと思われる）、「G40A C20A」「G30A T20A」（PF の定格電流と、つなぐ相手 C（コンデンサ）・T（変圧器）の電流）。

## まだ決まっていないこと

- 旧様式の「MCB 40A」「MCCB 200A」（PCS の手前）は、新様式の図面には無い。落としてよいか。
- 旧様式の LBS の「7200V」「PF×3」の行が、新様式（見本）では、省かれたり、「200A G20A T10A 40kA」の形に変わったりしている。標準の形はどれか。
- スケッチの範囲の書き方（例：「CUT 30〜40m」）を、図面の長さ（約30m）にどう直すか。

## 正解表づくりの進め方

1. 見本（完成形）の答えを、アプリの項目の形にする
2. スケッチごとに、「読み取れるはずの答え」を作る（読み取れない項目は、質問になるのが正解）
3. 御社のサーバーで、スケッチ・旧様式を読み取らせて、点数をつける（本物の API キーが要るので、サーバーで実行する）
