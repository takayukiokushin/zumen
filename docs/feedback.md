> 変圧器の台数は手入力の方がいいかなと感じたが、技術的に難しい場合は、
> 上下のカーソルで1台ずつ増減させるのではなく、ドロップダウンから選ばせてほしい。

- **状態**：**反映済み**
- **対応**：`transformerCount` を数値入力からドロップダウン（1〜50）に変える。
  手入力も技術的には可能なので、**手入力＋ドロップダウンの併用**にする

### ⑤ 変圧器の入力欄は、何台目かが見て分かるようにする

> 1台目の情報、2台目の情報と順番に入力する欄になっているが、
> どこからどこまでが1台目なのかが分かりにくい。今自分が何台目まで打ったかが
> 視覚的に分かりにくい。罫線を分かりやすくするとか、網掛けの色を1台目と2台目で
> 変えるとかして、明確に分かれるようにしてほしい。
> 台数が増えると目が疲れる原因にもなる。

- **状態**：**反映済み**
- **対応**：繰り返しグループ（変圧器・低圧分岐・受電設備エリアなど

  - 1台ごとに枠で囲い、背景色を交互に変える
  - 入力済みの台には印を付け、どこまで打ったかが一目で分かるようにする

- **状態**：**反映済み**

- **対応**：高圧進相設備を繰り返しグループにし、コンデンサ1台ごとに

- **決定**：容量も台ごとに変わる → 容量とリアクトルの有無を台ごとに持たせた（2026-10-20）

### ⑨ 変圧器より下がぐちゃぐちゃになる

> 事前ヒアリングから作成した図面が結構形が崩れていて思ったものになっていません。

  - 受電設備の枠は、結線せずに置いたものを含めない幅にした（受電設備の外のため）

#### ⑯⑰⑱ でやったこと（第2便）

**結線の持ち方を変えた。**
これまでは「線の端が接続点の近くにある」だけで、つながっている扱いだった。
そのため動かすたびに少しずつずれ、最後には離れてしまっていた。

いまは線の端が「**どの記号の、どの接続点につながっているか**」を覚えている。
記号を動かしても差し替えても回しても、線の端は必ずその接続点の真上に来る。
ずれは0。画面で見たままが、そのまま印刷に出る。

- ⑯ 動かす・回す・差し替える・消す、どの操作でも結線は外れない。
  片側だけつないである線は、縦なら縦・横なら横のまま伸び縮みする
- ⑰ 動かしている途中、結線がまっすぐになる位置と、ほかの機器と揃う位置に**吸い付く**。
  吸い付いた位置には**うすい目安の線**が出る。線の端も、接続点に近づけると吸い付く
- ⑱ 記号を差し替えると、つながっている側の接続点がその場に残るように置き直し、
  前後の線が新しい記号の大きさに合わせて自動で伸び縮みする

**あわせて直した不具合**：横に倒して置く記号（VT手前のPFなど）で、
図面の計算と実際の描画で回し方が食い違っていて、接続点が2ドットずれていた。
計算を一本化して直した。これが「よく見ると線がつながっていない」の原因だった。

図面全体を直したいときは、図面画面の**「結線を整える」**を押す。
近くにある線の端を接続点に結び直し、ぴったり合わせる。

検証は `pnpm check`（変圧器3台・コンデンサ2組・低圧回線2本の図面で、
動かす・吸い付く・差し替える・回す・消すを自動で確認）。

#### ㊼ PC・LBSの定格電流

| | 1行目 | 2行目 |
|---|---|---|
| PC | `30A`（本体の定格電流） | `F:10A`（ヒューズの定格電流） |
| LBS | `200A`（本体の定格電流） | `G50A T30A 40kA` |

LBSの2行目は、半角スペース区切りで3つ並べる。

1. `G` ＋ PFの定格電流（例 `G50A`）
2. 負荷側の記号 ＋ 電流（変圧器 `T` ／ コンデンサ `C` ／ モーター `M`）
3. 許容できる短絡電流（例 `40kA`）

**自動で入る値**：LBS本体 `200A`、短絡電流 `40kA`、
負荷側の記号は変圧器の手前なら `T`、コンデンサの手前なら `C`。
すべて一覧から選べて、**手入力もできる**。

`pnpm check` で毎回見るようにした。

#### ㊾ 「結線を整える」

**これまでの処理**：線の端を接続点に合わせるだけだった。

1. つなぎ先を覚えていない線の端が、接続点の6単位以内にあれば結びつける
2. 結びついている端を、接続点の真上にぴったり置き直す
3. 片側だけ結びついている線は、縦なら縦・横なら横のまま伸び縮みさせる

**いまの処理**：図面全体を見て、次の順に直す。

| | 直すこと | 直せないとき |
|---|---|---|
| 1 | 線の端を接続点に合わせる（従来どおり） | — |
| 2 | 余分な線を消す（長さ0・まったく同じ線） | — |
| 3 | 宙に浮いた線の端を、24単位以内の接続点につなぐ | 印を出す |
| 4 | 記号に突っ込んでいる線を、記号のふちまで引っ込める | 通り抜けている線は、2本に割らないと直せないので印を出す |
| 5 | 重なっている文字をずらす（元の位置から64単位まで） | 印を出す |
| 6 | 用紙に対して図面が大きすぎないか見る | A3や横向きを勧める |

**直したあとにもう一度調べ直し**、残った問題を
図面の上に**赤い印**で出し、画面上にも一覧で出す。

つなぐ距離を24単位（記号の枠の半分）に抑えてあるのは、
広げすぎると関係のない接続点に勝手につないでしまうため。

#### 51 用紙と向き

図面画面に **A4／A3／縦／横／用紙で見る** のボタンを足した。
切り替えるとその場でプレビューが変わり、印刷もその用紙で出る。
用紙の設定は図面と一緒に保存される。

A3は作図できる範囲がA4の1.41倍になるので、
**同じ図面が紙の上で大きく（読みやすく）出る**。

**できていないこと**：横向きを選んだときの「レイアウトの組み直し」。
いまは**縮めて用紙に収めている**だけで、縦長の図面を横向きの紙に
置き直す（たとえば主回路を2列に折り返す）ところまではやっていない。
そのため縦長の図面を横向きにすると、小さく表示される。
組み直しは、どこで折り返すかの決め方から相談したい。

#### ㊹ 段で揃えるようにした

これまでは列ごとに上から順に積んでいたため、PCやLBSの有無で変圧器の高さがずれていた。
**「段」という考え方**に変えた。

```
母線 ──────────────────────────────
  0段目  PC
  1段目  LBS
  2段目  VCS
  3段目  SR（直列リアクトル）
  4段目  本体（変圧器・コンデンサ）  ← どの列でもここに揃う
```

同じ段の機器は、どの列でも同じ高さに来る。
PCやLBSが無い列は、その段を空けたまま**母線からの線を長く引く**。
どの段も誰も使っていなければ、その段は詰める（1台だけの図面が無駄に縦長にならない）。

#### ㊸ PCが消えない件 — 調べた結果

**いまのプログラムでは再現しませんでした。**

| PC | LBS | 図面に出るもの |
|---|---|---|
| なし | なし | （どちらも出ない） |
| あり | なし | PCのみ |
| なし | あり | **LBSのみ** |
| あり | あり | PC → LBS の順 |

#### ㉞ PASをひとかたまりにした

図面のデータに「**親**」と「**どのスロットに入っているか**」を持たせた。
PASに内蔵するZCT・VT・LAは、PASの子として記録される。

- **動かす** … PASをつかむと、中の3つも同じだけ動く
- **消す** … PASを消すと、中の3つも一緒に消える
- **差し替える** … 新しい記号に同じ名前のスロットがあればそこへ置き直し、
  無ければ中身も一緒に消える（LBSに差し替えるとZCT・VT・LAは消える）
- **選ぶ** … 中のZCTを押しても、まずPASごと選ばれる。
  選んだ状態でもう一度押すと、中の部品だけを選べる（部品の文字を直したいとき）

「内蔵の有無そのもの」は、これまでどおりヒアリングの回答で決まる。
VT内蔵を「あり」にすればVTが増え、「なし」にすれば消える（㊱の修正で、
回答を変えればすぐ図面に出るようになった）。

#### ㊱ ヒアリングが図面に反映されない

**原因**：図面を一度でも開くと、その時点の図面が保存され、
次からは**保存してある図面がそのまま出る**ようになっていた。
手で直した図面を勝手に作り直さないための作りだったが、
一度も直していない図面まで固定されてしまっていた。

**直し方**：図面に2つの印を持たせた。

- **どの回答から作ったか**（回答の中身を短い印にしたもの）
- **人が手で直したか**

| 状態 | どうなるか |
|---|---|
| 手で直していない | 回答が変われば、**開くたびに自動で作り直す** |
| 手で直してある・回答は同じ | そのまま開く |
| 手で直してある・回答が変わった | そのまま開き、**上に案内の帯**を出す。<br>帯の「回答から作り直す」で作り直せる（「操作を戻す」で元に戻せる） |

これで「入力したのに出てこない」は起きなくなり、
手で直した図面が黙って消えることもない。

### 読み取り精度の作り込み

完成形のPDF1枚と、それをあえて雑に手書きした図面を数パターン受け取り、
手書き→完成形の読み取り精度を上げる。

やること：

1. 完成形PDFを読み、**いまのアプリで同じ図面を出せるか**を試す。
   足りない記号・構成ルールを洗い出す
2. 手書きと完成形を突き合わせ、**読み取りの指示文**（`packages/ai/src/prompt.ts`）を直す
3. 「この手書きからは、この回答が出るべき」という**答え合わせの組**を
   `docs/samples/` に残し、`pnpm check` で毎回検証できるようにする
4. APIキーが入ったら、同じ教材で**アプリ自身の読み取り精度を実測**する

着手前に確認すること：

- 完成形PDFは古いデータで、記号や書き方が現在の流儀と一部違う。
  気づいた差異はその都度ユーザーに確認する
- 顧客名・事業場名をそのまま記録してよいか、伏せるか
