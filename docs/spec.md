# 単線結線図作成アプリ 開発仕様書

高圧・自家用電気工作物の「単線結線図」を作成するためのアプリケーション。
現在はWindows上のCADソフトで作図しているが、macOSへ移行したい。同等のmacOS向けアプリが
存在しないため新規に開発する。

---

## 0. 決定事項（着手前の確認結果）

| 項目 | 決定 |
|---|---|
| 配布方針 | **Web本体 + Electronラップ**。コード資産を一本化する |
| 対象プラットフォーム | macOS / Windows（Electron）＋ モバイル（iPad・Android・iOS）は**MVPから閲覧のみ**対応 |
| データ保存 | **クラウド中心（サーバー保管）** |
| Claude APIキー | **サーバー経由**。端末にキーを配布しない |
| 利用者・認証 | 社内数名。ID/パスワードによるログイン。社外共有機能は作らない |
| 出力形式 | PDF のみ（PNG・SVG の保存は不要。DXF等のCAD互換出力も不要） |
| AI解析 | MVP段階から導入 |
| アプリ内コメント機能 | MVP外（将来追加。データ構造に後付けの余地を残す） |
| オフライン動作 | AI解析のみネット必須。作図・編集・PDF出力はオフラインで動作させる |

### 図面に印字する分界点の文言（確定）

| 状況 | 記載する文言 | 位置 |
|---|---|---|
| 3点一致（約99%） | **財産・責任分界点** | 引込点の図記号とPASの間に引いた横線 |
| 3点不一致（約1%） | **財産分界点** | 引込点と同一地点 |
| 3点不一致（約1%） | **責任分界点** | 該当するLBSまたはVCBの図記号の中央に引いた横線 |

※ ナレッジベース原文の「保安上の責任分解点」という表記は使わない。文言は記号マスタの
`defaultLabel` として持たせているため、後から変更できる。

## 1. 背景・目的

- JIS（および関連業界規格）で定められた電気用図記号を用いて、単線結線図を正確かつ効率的に作成する。
- 現地調査時にラフに手書きした図面や写真・PDFを取り込み、清書された図面のたたき台を自動生成し、作図工数を削減する。
- 案件（現場）ごとに異なる固有情報を作図前にまとめてヒアリングし、後工程での手戻りを防ぐ。

## 2. 利用者・利用シーン

- 利用者：電気設備の設計・保安業務を行う技術者（1名〜少人数）＋ 作図を担当する事務員
- シーン：
  1. 現地調査 → 手書きメモ・ラフスケッチ（写真 or スキャンPDF）を作成
  2. アプリでプロジェクトを新規作成し、事前質問に回答
  3. スケッチ画像/PDFをアップロード
  4. アプリが構成案（機器・結線）を提示 → 利用者が確認・修正
  5. JIS記号を用いた正式な単線結線図としてレンダリング
  6. PDF等で出力・保存

## 3. 全体の利用フロー

```
[新規プロジェクト作成]
      ↓
[事前ヒアリング（質問フォーム）] ── 顧客名/事業場名/契約電力 等
      ↓
[現地スケッチ画像 or PDFをアップロード]
      ↓
[AI解析：手書き内容 + ヒアリング回答から機器リスト・接続関係を構造化]
      ↓
[構造化データを人間が確認・修正（重要：AI出力は「たたき台」）]
      ↓
[JIS図記号ライブラリを用いて単線結線図を自動レンダリング]
      ↓
[エディタ上で微調整（位置・注記・線種等）]
      ↓
[PDF/PNGとして出力・プロジェクト保存]
```

## 4. 機能要件

### 4.1 事前ヒアリング機能

プロジェクト作成時に質問をフォーム形式で提示し、回答を保存する。質問項目は
カスタマイズ・追加削除可能な設計とする（質問定義はデータとして持つ）。

### 4.2 スケッチ/PDFアップロード機能

- 画像（JPEG/PNG/HEIC）およびPDFに対応
- 複数ページ・複数画像に対応

### 4.3 AI解析機能（手書き→構造化データ）

- アップロードされた画像/PDFとヒアリング回答をClaude API（マルチモーダル）に渡し、
  機器リスト・接続関係・特記事項候補をJSONで抽出する。
- **AIによる抽出結果は「精度100%を保証しない下書き」として扱う。** 抽出後、人間が
  一覧画面で確認・修正できるUIを必ず用意する。電気設備図面は保安上の重要書類のため、
  最終責任は必ず人間側に残す設計とする。
- スケッチだけでは判断できない項目は、AIが作図前に一問一答形式で追加質問を出す
  （分岐点ごとの確認質問はナレッジベースに登録する）。

### 4.4 図面生成エンジン

確定した構成データをもとに、単線結線図をSVGベースで自動レイアウト・描画する。
自動レイアウトはあくまで「たたき台」の位置決めであり、エディタで自由に再配置できること。

### 4.5 JIS図記号ライブラリ

`packages/symbols` を参照。記号にはメタデータ（名称・定格入力欄・接続点座標）を持たせる。

### 4.6 図面編集機能（最重要）

現場の知識を持つ技術者が「これをこう直して」と簡単な指示を出し、パソコンに詳しくない
事務員がその指示だけで迷わず修正できる、直感的な編集操作性を最優先で設計する。

- 記号の追加・削除・変更（別の記号への差し替え）が、クリック数少なく行えること
- ドラッグ&ドロップによる記号配置・移動
- 結線の手動追加・修正・削除
- テキスト注記の追加・編集
- 表題欄の編集
- 元に戻す / やり直す（必須）

### 4.7 出力機能

- PDF出力（印刷・提出用。最終ゴール成果物）
- PNG出力
- DXF等CAD互換形式への出力は不要

### 4.8 プロジェクト管理

現場（案件）ごとにプロジェクトとして保存・呼び出し。ヒアリング回答・アップロード画像・
構成データ・図面データを一式で管理する。

### 4.9 レイヤー（図面の種類）：停電範囲図・絶縁耐力試験範囲図など

単線結線図の上に、**赤い印を重ねた図面**を作る機能。元の単線結線図は変えない。使い方は `docs/layers.md`。
この節の数値は、`pnpm check`（`scripts/check-spec.ts`）が、プログラムの値と一致しているかを確かめる。

**決めたこと（利用者との確認結果）**

- 種類は、固定の「停電範囲図」「絶縁耐力試験範囲図」と、名前を自由に付けられる追加分3つ（合計5）。
  印刷の表題で変わるのは「図面名称」の部分だけ（事業場名・お客様名・入力済みの図面名称は変えない）。
- 赤い印は、どの種類でも使える。**すべて赤・少し太め。カラーで印刷する前提**（白黒印刷は考えない）。
- 「図面の種類」のリストは、印刷のボタンの近くに置く。**図面を開くときは、いつも単線結線図から**。
- レイヤーを選んでいるあいだは、**元の図面を薄く表示して動かせない**。触れるのは、そのレイヤーに置いた印だけ。
- **印刷・PDF化は、選んでいる1種類だけ**。向き（縦・横）も、レイヤーごと。
- 「操作を戻す」は、**レイヤーごとに別々**。
- 複製のときは、**どのレイヤーも一緒に複製するか**を聞く（最初は何も選ばない）。
- 単線結線図に書いたメモは、**表題以外、どのレイヤーの印刷にも出る**。
- 単線結線図では、赤い印のボタンは薄く表示し、押すと「このレイヤーでは選択できません」と出す。
- 置いた印は、**近くの機器について動く**。つないだ機器が無くなった×印・接地・点・矢印・渡り線は、画面にも印刷にも出さず、保存のときにデータから外す。
  文字と枠は、消さずに最後の場所に残す。
- 元の図面が変わったときは、レイヤーを開くと一度だけポップアップで知らせ、「確認した」を押すまで帯を残す。
- 手書きの見本が届いたら、見た目（線の太さ・弧のふくらみ・文字の位置など）を合わせる（まだ届いていない）。

**赤い印の種類**

| 印 | 置き方 | 決まり |
|---|---|---|
| メモ | 「メモを追加」 | 文字の大きさは記号の横の文字の1倍〜5倍、太字にできる |
| ×印 | 開閉器をクリック | 正方形・太さ均一。大きさは下の表。開閉器の中央に付け、ずらせる。同じ開閉器に複数 |
| 接地 | 2回クリック（つなぐ場所→置く場所） | いつも下向き。横棒あり／なし。つなぐのは母線の途中か記号の接続点。横に文字 |
| 赤い枠 | ドラッグ | 種類は停電範囲・充電範囲・印加範囲。近くに文字（四隅の外側から選ぶ） |
| 丸い点 | クリック | 母線の途中・記号の接続点の近くなら吸い付く（Alt で切る） |
| 印加点の矢印 | 丸い点をクリック | 1つの点に1本。尾の向きは8方向、長さは自由。文字は最初「印加点」 |
| 渡り線 | 点を順にクリック | 点と点を弧の線でつなぐ。続けて引ける。同じ2つの点は重ねない |

| ×印の大きさ | 一辺 | 太さ |
|---|---|---|
| 小 | 36 | 9 |
| 中 | 60 | 12 |
| 大 | 84 | 15 |

| 赤い枠の種類 | 斜線 |
|---|---|
| 停電範囲 | なし |
| 充電範囲 | あり |
| 印加範囲 | なし |

| 渡り線の弧の形 | ふくらみの高さ（点と点の距離に対して） |
|---|---|
| 直線 | 0% |
| ゆるい弧 | 12% |
| 普通の弧 | 25% |
| すごく丸い弧 | 50% |

| 寸法・太さ | 値 |
|---|---|
| 文字の大きさ | 1〜5倍 |
| 線の太さ（枠・接地・渡り線・矢印） | 2 |
| 斜線の太さ | 0.8 |
| 斜線の間隔 | 6 |
| 丸い点の半径 | 5 |
| 矢印の長さ | 20〜200（最初は40） |

**データ**：図面の保存データ（1つのJSON）の `layers` に入る。レイヤーは `id`・`name`（追加分のみ）・`items[]`・`orientation`・`seen`
（最後に手を入れたときの元の図面の記録。いまの元の図面と違えば「要確認」）。種類は `text`・`cross`・`ground`・`area`・`dot`・`arrow`・`link`。
バージョンアップ前の古い画面から保存して、レイヤーが消えるのは、サーバーが断って防ぐ。

**確認のしくみ**：`scripts/check-drawing/part4〜11.ts`（各機能）、`docs/golden/L1〜L3`（赤いレイヤーの印刷の見本）、`pnpm selftest`（保存して開いても、そのまま戻る）。

## 6. 技術スタック

- モノレポ：pnpm workspaces + TypeScript
- フロント：React + Vite、状態管理 Zustand + Immer（Immerのパッチでundo/redo）
- 作図キャンバス：SVGを自作コンポーネントで実装（接続点への吸着・直交配線・記号差し替え時の結線維持のため、汎用図形ライブラリは使わない）
- サーバー：Node + Hono、PostgreSQL、オブジェクトストレージ
- AI解析：サーバーからClaude API（画像入力＋構造化出力）
- PDF/PNG出力：ブラウザ側でSVG→ベクタPDF化
- デスクトップ：Electron（macOS / Windows インストーラ）。
  画面はサーバーが配信するWeb版をそのまま読み込む薄い殻とし、Web版と機能差を作らない。
  接続先URLは初回起動時に入力し、端末のユーザーデータに保存する（APIキーは端末に置かない）。

## 7. 非機能要件・注意事項

- **著作権**：JIS C 0617（電気用図記号）等の規格書そのもの（図版・レイアウト）を複製しない。
  規格の仕様（形状・意味）を参照しつつ、図記号セットは独自に描き起こす。正確な仕様確認のため、
  日本規格協会（JSA）から正規に規格書を入手することを推奨。
- **法令・保安上の位置づけ**：本アプリは作図支援ツールであり、電気事業法・保安規程等への
  適合性の最終確認は有資格者（電気主任技術者等）が行うことを前提とする。
- **AI解析精度の限界**：手書きスケッチの認識には限界があるため、人間の確認ステップを必須化する。
- **APIキー**：Claude APIキーはサーバー側にのみ保管し、クライアントに配布しない。

### 8.1 反映済みの現場ルール（抜粋）

- **PASの内蔵機器はSOGの有無で決まる。**
  SOG（GR/DGR）があればZCTが内蔵され、VTは有無の両方があり得る。
  SOGが無ければVTとZCTは入らない（LAだけは入ることがある）。
  → 質問の出し分け・構成ルール・AI解析の矛盾検出の3か所に反映済み。

## 9. 事前質問リスト

### 9.1 共通ヒアリング項目

1. 表題欄への記載名（事業場名称と異なる書き方をする場合）
2. 事業場名称・現場住所
3. 契約電力・受電電圧（高圧受電のみ。特別高圧受電は扱わない）
4. 引込設備の仕様（ケーブル種別・条数 等）
5. 変圧器の台数・容量・結線方式
6. 保護継電器（OCR/OVR/UVR等）の仕様
7. 主要遮断器・断路器の仕様
8. 接地方式・接地抵抗値等の特記事項
9. 図面番号・版数・作成者名・作成日
10. その他現場固有の特記事項・注意書き

### 9.2 機器別詳細質問

ナレッジベースに登録された「バリエーションの分岐点」から自動生成する。
スケッチ画像だけで判別できる場合はAIが自動判定し、判別できない場合のみユーザーに質問する。

- **責任分界点**：3点一致ですか？（はい/いいえ）
- **受電設備エリア**：電気設備は何箇所に分かれていますか？（画像から1箇所と明確に判別できる場合は質問不要）
- **主遮断装置**：形式は？（PFS形 / CB形 / それ以外［高圧マンション・電柱上構成］）
- **PAS**：設置の有無 / 制御装置の種類（なし・GR・DGR）/ VT内蔵の有無 / LA内蔵の有無 /
  定格電圧（6600V・7200V）/ 定格電流（100・200・300・400A）
- **VCT**：位置は？（電柱上 / 電気設備内）
- **引込ケーブル**：付設方法（埋ケ/架ケ）/ 構造（CV/CVT）/ 定格電圧 / 断面積
  （14・22・38・60・100・150・200・250 mm² から選択。**一覧にない値の手入力も可**）/ 長さ（不明なら「-」）

## 9.2 結線（線）の編集についての要望

作図の使いやすさで一番のネックになるのが、記号と記号をつなぐ線の編集。
実際に使ってみないと詰められない部分が多いため、要望として記録しておく。

- 線の**修正・削除・追加**を簡単にしたい
- **縦線・横線がずれない**こと。ずれたときに簡単に揃えられること
- 線の**移動**を簡単にしたい
- 線の**伸縮**を簡単にしたい
- 記号を動かしたときに、つながっている線が**自動で伸縮・補正**されるアシストがほしい

### 現時点の対応

- 移動・伸縮は**格子に吸着**させ、線は**縦か横のどちらかに自動で揃える**（斜めにならない）
- 線を選ぶと**両端にハンドル**が出て、端だけを動かして伸縮できる
- **記号を動かすと、つながっている線の端が一緒に動く**（線が切れない）
- 線の追加は、始点と終点をクリックする方式。縦横に自動で揃える

実際に使ってみたうえで、整列コマンドや自動経路の要否を詰める。

## 9.3 想定している使い方（追記）

現地調査の**下見に持って行く下図**としての使い方を想定する。ヒアリング回答から
図面のたたき台を出し、印刷して現地で書き加え・修正したうえで、その結果を
AI解析に読み込ませる。

- 位相計の丸の中の表記（`cosθ` としている）
- DSR の正式名称
- 手書きの見本（停電範囲図などの赤い印の見た目）の到着待ち。届いたら、線の太さ・弧のふくらみ・文字の位置などを合わせる
- 図面を一度も編集せずに開き直すと、向き（縦・横）が戻ることがある（以前からの不具合。直し方を利用者が決める）
- 「結線を整える」の重なりの確認が、大きくした文字の大きさを考えていない（直すかを利用者が決める）
- 赤いレイヤーの画面操作を、Safari・Firefox・iPhone・Windows で確かめる（付録B。利用者の手で）
- 事務員への「指示の出し方」の具体イメージ（MVP外だが、将来のコメント機能の設計に影響）
