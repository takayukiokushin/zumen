# サーバーの状態の見かた（管理者向け）

サーバーが元気かどうかを、画面で確かめられます。**管理用のアカウント**でログインしたときだけ使えます。

## 見かた

1. 画面の右上の**「利用者の管理」**を押します。
2. いちばん上の**「サーバーの状態」**に、次のことが出ます。「最新にする」を押すと、読み直します。

| 項目 | 意味 |
|---|---|
| 最後に成功した控え | いちばん新しい控え（バックアップ）の日時と、何日前か |
| 残っている控え | 控えが何日分あるか（10日分まで残します） |
| 直近の控えの失敗 | 控えを作ろうとして失敗したときだけ出ます。そのあと成功すれば消えます |
| ディスクの空き（案件のデータ） | サーバーのパソコンの、案件を置いているディスクの空き |
| ディスクの空き（控えの保存先） | 控えの保存先のディスクの空き |
| エラー（想定外のもの） | 過去24時間・過去7日に、サーバーが記録した想定外のエラーの件数と、最後に起きた時刻 |
| 版・動いている時間 | サーバーの版と、起動してからの時間 |

エラーの中身は、サーバーの `data/error.log` に残っています（パスワードや案件の中身は入っていません）。

## 画面の上の帯

次のどれかのとき、管理用のアカウントでログインした画面の上に、**赤い帯**が出ます（「状態を見る」で、上の画面が開きます。「閉じる」で、その画面を開いているあいだは隠せます）。

- 控えが**2日以上**取れていない（まだ1つも無い・保存先が決まっていない場合も含む）
- ディスクの空きが**10%以下**（案件のデータのディスク、または、控えの保存先のディスク）
- 直近の控えが失敗している

帯は、ログインしたとき・30分おき・この画面に戻ってきたときに確かめます。エラーの件数は、状態の画面に出すだけで、帯では知らせません。

## 帯が出たら

- **「控えの保存先が決まっていません」**：サーバーの `.env` に `BACKUP_DIR` を書いて、サーバーを起動し直します（手順書 `docs/server-setup.md`）。
- **「控えが○日以上取れていません」「直近の控えが失敗しています」**：サーバーが動いているか、控えの保存先（Dropbox などのフォルダ）が使えるか、ディスクに空きがあるかを確かめます。サーバーを起動し直すと、今日の控えが無ければ、すぐ1つ作ります。
- **「ディスクの空きが少なくなっています」**：不要なファイルを消して、空きを作ります。空きが無くなると、案件を保存できなくなります。

## 作る側のための確認

- 判断の決まり（2日・10%・エラーの数え方）は、`apps/server/src/status-rules.ts` にあり、`pnpm check`（`scripts/check-status.ts`）が確かめます。
- 管理用だけが見られること・パスワードなどが含まれないことは、`pnpm selftest` が確かめます。
