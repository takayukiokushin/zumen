# サーバー用Macの設置手順書

会社の Mac mini を「サーバー役」にして、社内のみんながブラウザから使えるようにするための手順。
**専門知識は要りません。** 上から順にやれば終わります。

> **呼び出し方**：サーバー用のMacの Claude Code で
> 「**今から会社のMacをサーバーにする設定を行います。以前作成したマニュアルを出して**」
> と言えば、この手順書を順番に出します。
>
> **これが出ないとき・この手順書が開けないとき** → [困ったとき用の1枚](first-aid.md)。
> そちらは**印刷して手元に置いておくこと**（この手順書はアプリのフォルダの中にあるため、
> フォルダが無い状態では読めない）。

---

## そもそも何をするのか

```
［サーバー役の Mac mini］ ← 常に電源を入れておく1台
   ・案件のデータを保管する
   ・APIキーもここだけに置く
        ↑
   社内のネットワーク
        ↓
［他のパソコン・iPad］ ブラウザで住所を開くだけ
   ・何もインストールしない
   ・全員が同じ案件を見られる
```

**アプリを入れるのはサーバー役の1台だけ**です。他のパソコンはブラウザで見るだけ。

### この手順書の中身

| | 内容 |
|---|---|
| 第1部 | いまのパソコンを「サーバー役から外す」（はじめてなら飛ばす） |
| 第2部 | 会社の Mac mini をサーバーにする |
| 第3部 | 取扱説明書（日常の運用。**利用者の作り方・消し方**はここ） |
| 第4部 | **GitHubのリポジトリを「非公開」にする（いちばん最後）** |

> 第4部は**必ず最後**にやること。
> 先に非公開にすると、第2部のダウンロードができなくなります。

# 第1部　いまのパソコンを「サーバー役から外す」

すでに別のパソコンで試していた場合に行う。はじめての場合は飛ばしてよい。

## 1-1. APIキーを消す

ターミナルを開いて（`command + スペース` →「ターミナル」）、次を貼り付けて Enter。

```sh
cd ~/Desktop/zumen
rm .env
```

> フォルダの名前が違う場合は、`cd ` と打って（うしろに半角スペース）、
> デスクトップのフォルダをターミナルの窓に**ドラッグ**してから Enter。

これでAPIキーが消えます。

## 1-2. 残したい案件があれば控えを取る

試しに作っただけなら不要。残したいものがあれば：

```sh
open ~/Desktop/zumen/data
```

開いたフォルダを丸ごとコピーして、あとでサーバー役のMacの同じ場所に置く。

## 1-3. フォルダごと捨ててよい

デスクトップの `zumen-...` フォルダをゴミ箱へ。
以降このパソコンからは、**ブラウザでサーバー役の住所を開いて使う**。

# 第2部　会社の Mac mini をサーバーにする

**ここからは、サーバーにする Mac mini で操作する。**

## 2-1. Node.js を入れる

ターミナルを開いて（`command + スペース` →「ターミナル」）：

```sh
node -v
```

- **`v22` 以上の数字が出た** → 2-2 へ
- **`command not found` と出た** → <https://nodejs.org/ja> を開き、**LTS** の大きいボタンからダウンロード。
  案内どおり「続ける」を押していけば入る。
  入れ終わったら**ターミナルを一度閉じて開き直し**、もう一度 `node -v` で確認

## 2-2. アプリをダウンロードする

1. <https://github.com/takayukiokushin/zumen> を開く
2. 緑色の **「Code」** → **「Download ZIP」**
3. ダウンロードフォルダのZIPを**ダブルクリック**（展開される）
4. できたフォルダを**デスクトップに移動**
5. フォルダの名前を **`zumen`** に変える（長い名前が付いているので、短くしておく）

> 中に同じ名前のフォルダがもう一段入っていることがある。
> **`test-mac.command` が見えるところ**まで進むこと。そこが本体。
> 以降この手順書では、この場所を `~/Desktop/zumen` と書く。

## 2-3. ダウンロードの警告を外す

ターミナルで `cd ` と打ち（cd のあとに半角スペース）、**デスクトップのフォルダをターミナルの窓にドラッグ**して Enter。続けて：

```sh
xattr -dr com.apple.quarantine .
```

> macOSが「インターネットから落としたファイル」として止めるのを、フォルダごと解除する。
> これをしないと、ダブルクリックのたびに警告が出る。

## 2-4. 動くか確かめる

```sh
./test-mac.command
```

初回は5〜10分かかる。画面が止まって見えても待つこと。

```
✓ 73件すべて正常です。このまま進めて問題ありません。
```

と出れば成功（件数は版によって増える。**「すべて正常」の一言**が出ていればよい）。最後に「実際の画面も確かめますか？」と聞かれたら、いまは `n`（Enter）でよい。

> **「問題が見つかりました」と出たら**、同じフォルダの `test-result.txt` の中身を見せること。

## 2-5. APIキーを置く

```sh
cp .env.example .env && open -e .env
```

テキストエディットが開くので、この行を探す。

```
ANTHROPIC_API_KEY=sk-ant-...
```

**`=` の右側をまるごと**、APIキーに置き換えて `command + S` で保存。

> `=` の前後に空白を入れない。引用符も不要。
> **このキーは、このMac miniだけに置く。** 他のパソコンには配らない。

使えるか確かめる：

```sh
pnpm --filter @zumen/server apikey
```

`✓ 利用券は使えます。` と出れば完了（かかる金額は1円未満）。

## 2-6. 控え（バックアップ）の場所を決める

**案件のデータはこのMac1台に貯まる。壊れたら全部なくなる。**
ドロップボックスなどの同期フォルダを指定しておけば、1日1回そこへ自動で控えが作られる。

```sh
open -e .env
```

一番下の行を、自分のパスに書き換えて保存（先頭の `#` を消す）。

```
BACKUP_DIR=/Users/ユーザー名/Dropbox/単線結線図_控え
```

## 2-7. 利用者を登録する

アカウントには**3つの種類**がある。

| 種類 | 書き方 | できること |
|---|---|---|
| **管理用** | `admin` | すべての案件＋**画面から利用者の管理**。編集中の案件も引き継げる |
| **標準** | `member` | 案件をみんなで共有する。ふだん使うのはこれ |
| **練習用** | `sandbox` | **自分が作ったものだけ**。他の人には見えず、他の人のも見えない |

### 作る

```sh
pnpm --filter @zumen/server user:add <ID> <名前> <パスワード> <種類>
```

最初に作るのは、この3つでよい。

```sh
pnpm --filter @zumen/server user:add kanri 管理者 ここにパスワード admin
pnpm --filter @zumen/server user:add fujielex 株式会社フジエレックス ここにパスワード member
pnpm --filter @zumen/server user:add renshu 練習用 ここにパスワード sandbox
```

- IDは半角の英数字（`.` `_` `-` `@` も使える）
- パスワードは**8文字以上**。会社名や年号をそのまま使わない
- 種類を省くと `member`（標準）になる

### 一覧を見る

```sh
pnpm --filter @zumen/server user:list
```

```
  管理用　  kanri	管理者
  標準　　  fujielex	株式会社フジエレックス
  練習用　  renshu	練習用
```

### 消す

```sh
pnpm --filter @zumen/server user:remove <ID>
```

> ⚠️ 動作確認のときに `test` というIDが作られることがある。
> **このパスワード（`testpass123`）は手順書に書いてあるので、社内の誰でも知り得る。**
> `user:list` に `test` が残っていたら、必ず消すこと。

### パスワードを変える

```sh
pnpm --filter @zumen/server user:passwd <ID> <新しいパスワード>
```

### これ以降は画面からできる

**管理用のアカウントでログインすると、右上に「利用者の管理」ボタンが出る。**
追加・削除・パスワードの再設定・ログインの解除は、そこから行える。
ターミナルを開く必要があるのは、**一番最初に管理用アカウントを作るときだけ**。

## 2-8. 自動で立ち上がるようにする

```sh
./install-autostart.command
```

これで、このMacにログインするたびにサーバーが自動で立ち上がる。
止まっても自動でやり直す。

## 2-9. 住所を控える

```sh
pnpm start
```

表示される**2行目**を控える。これが他のパソコンから開く住所。

```
サーバーを起動しました: http://127.0.0.1:8787
  社内の他のパソコンからは: http://192.168.11.28:8787   ← これを控える
```

確認できたら `control + C` で止めてよい（自動起動が設定済みなので、再起動後は勝手に立ち上がる）。

## 2-10. Macの設定を2つ変える

**① スリープさせない**
システム設定 → **ロック画面** → 「ディスプレイがオフのときに自動でスリープさせない」をオン。
スリープするとサーバーも止まる。

**② 自動ログインにする**
システム設定 → **ユーザとグループ** → 自動ログインをオン。
再起動後にログイン画面で止まると、サーバーが立ち上がらない。

## 2-11. 他のパソコンから開いてみる

別のパソコンのブラウザで、2-9で控えた住所を開く。

```
http://192.168.11.28:8787
```

ログイン画面が出れば完成。

**つながらないとき**：システム設定 → ネットワーク → ファイアウォール → オプション で
Node の通信を許可する。

# 第3部　取扱説明書（日常の運用）

## 毎日の使い方

**サーバー役のMac miniでは、何もしなくてよい。**
電源が入っていれば、自動で動いている。

**使う人は**、ブラウザで住所を開いてログインするだけ。

```
http://192.168.11.28:8787
```

> Safari の「ファイル → **Dockに追加**」で、アプリのように Dock から開けるようになる。
> Chrome / Edge なら「ページをアプリとしてインストール」。

## 動いているか確かめる

ブラウザで住所を開いて、ログイン画面が出れば動いている。

出ないときは、サーバー役のMacで：

```sh
cd ~/Desktop/zumen
./start-server.command
```

## 手で止める・動かす

| やりたいこと | すること |
|---|---|
| 止める | 黒い画面で `control + C`、またはウィンドウを閉じる |
| 動かす | `start-server.command` をダブルクリック |
| 自動起動をやめる | `uninstall-autostart.command` をダブルクリック |

## 利用者を増やす・パスワードを変える

**ふだんは画面から行う。** 管理用のアカウントでログインし、右上の**「利用者の管理」**を押す。

- 追加（種類も選べる）
- パスワードの再設定
- **ログインの解除**（まちがえ過ぎて止まっている人を、待たずに入れるようにする）
- 削除

> 最後の管理用アカウントと、自分自身は消せないようにしてある。

ターミナルからでも同じことができる。

```sh
cd ~/Desktop/zumen

pnpm --filter @zumen/server user:add <ID> <名前> <パスワード> <admin|member|sandbox>
pnpm --filter @zumen/server user:passwd <ID> <新しいパスワード>
pnpm --filter @zumen/server user:remove <ID>
pnpm --filter @zumen/server user:list
```

## バックアップ

`.env` に `BACKUP_DIR` を書いてあれば、**起動時と1日1回、自動で控えが作られる**。
30世代まで残り、古いものから消える。

手で取りたいときは：

```sh
pnpm --filter @zumen/server backup "/Users/ユーザー名/Dropbox/単線結線図_控え"
```

控えの中には、日付のフォルダ（例 `20261026-130131`）ができる。
その中の **`zumen.db`（案件と利用者のデータ）と `files/`（現地の写真）** が控えの本体。

> **控えに入らないもの：`.env`（APIキー）。** 別にしまっておくこと。
> 無くなっても、APIキーは発行し直せば使える。

> **`data/` フォルダそのものをドロップボックスの中に置くのは避ける。**
> 書き込み中に同期がかかるとデータが壊れることがある。

## 控えから戻す（復元）

こんなときに使う：案件を消してしまった、データが壊れた、Macを入れ替えた。

### 先に知っておくこと

- **戻すと、その控えを取った時点まで、すべてが戻る。**
  控えのあとに作った案件、直した図面、**利用者の追加やパスワードの変更**も消える
  （利用者のデータも同じファイルに入っているため）。
- そのため、戻す前に**いまの `data` を捨てずに脇へ避ける**（手順2）。やり直せる。
- **1件だけ戻したいときは、全部は戻さない。** 下の「控えの中の案件を見るだけ」を使う。
- **`zumen.db` だけを上書きしてはいけない。**
  `data/` には `zumen.db-wal`、`zumen.db-shm` という付属のファイルがあり、
  これが残ったまま古い `zumen.db` を置くと、**戻したつもりで戻らない**
  （試したところ、消した案件は戻らず、変えた名前もそのままだった）。

### 手順

サーバー役のMacで、ターミナルを開いて行う。

**1. サーバーを止める**

自動起動にしているとき（止めても自動で立ち上がり直してしまうので、この方法で止める）：

```sh
launchctl unload ~/Library/LaunchAgents/jp.co.fuji-elex.zumen.plist
```

自動起動にしていないとき：黒い画面で `control + C`。

**2. いまの `data` を、脇へ避ける**（捨てない）

```sh
cd ~/Desktop/zumen
mv data "data.戻す前-$(date +%Y%m%d-%H%M%S)"
```

**3. 控えから、新しい `data` を作る**

控えには2種類ある。どちらか一方を行う。

**A. 自動の控え**（`BACKUP_DIR` の中の日付フォルダ）

日付のフォルダは、**戻したい日のもの**を選ぶ（新しい順に並べて見る）。

```sh
mkdir data
cp "控えの場所/日付フォルダ/zumen.db" data/
cp -R "控えの場所/日付フォルダ/files" data/files
```

**B. 更新前の控え**（`update-mac.command` が作ったもの）

ホームフォルダ（Finderの左にある家のマーク）の `zumen-更新前の控え` の中に、日付のフォルダがある。
中の `data` を、**フォルダごと**置く（`zumen.db` だけを取り出さない）。

```sh
cp -R "$HOME/zumen-更新前の控え/日付/data" data
```

**4. サーバーを動かす**

```sh
launchctl load -w ~/Library/LaunchAgents/jp.co.fuji-elex.zumen.plist
```

自動起動にしていないときは `start-server.command` をダブルクリック。

**5. 戻ったか確かめる**

ブラウザで住所を開き、ログインして、**案件の一覧**に戻したい案件があるか見る。
開いて、図面と回答が控えの時点のものか確かめる。

**6. 脇へ避けた `data` は、しばらく残す**

`data.戻す前-日付` は、問題がないと分かってから（数日後）捨てる。
**戻したあとで「やっぱり戻す前のほうがよかった」となっても、これがあれば元へ戻せる。**

### 控えの中の案件を見るだけ（1件だけ救いたいとき）

全部は戻したくないが、控えの時点の案件を見たいときは、
**控えを別の入口（ポート番号 8788）で開いて**、図面を見る。いまのデータには触らない。

```sh
mkdir "$HOME/zumen-控えを見る"
cp "控えの場所/日付フォルダ/zumen.db" "$HOME/zumen-控えを見る/"
cp -R "控えの場所/日付フォルダ/files" "$HOME/zumen-控えを見る/files"

cd ~/Desktop/zumen
BACKUP_DIR= DATA_DIR="$HOME/zumen-控えを見る" PORT=8788 pnpm --filter @zumen/server start
```

別のタブで `http://127.0.0.1:8788` を開く（利用者のIDとパスワードは控えの時点のもの）。
見終わったら、黒い画面で `control + C` を押し、`zumen-控えを見る` フォルダを捨てる。

- 図面は、画面の書き出し（SVG・PNG）や印刷で取り出せる。回答は画面を見ながら、いまのアプリに入れ直す。
- **ここでは編集しない。** 編集してもいまのデータには反映されない。
- **コマンドの頭の `BACKUP_DIR=` は消さない。** 消すと、古い内容の「新しい控え」が
  自動で作られ、本物の最新の控えと見分けがつかなくなる。

## APIキーを入れ替える

```sh
cd ~/Desktop/zumen
open -e .env
```

書き換えて保存したあと、**サーバーを入れ直す**（キーは起動時に読み込むため）。

```sh
pnpm --filter @zumen/server apikey   # 確認
```

## 困ったときの対処

| 症状 | 原因 | どうするか |
|---|---|---|
| 他のパソコンからつながらない | サーバーが止まっている | サーバー役のMacで `start-server.command` |
| 〃 | 住所が変わった | `pnpm start` で表示される住所を確かめる。IPアドレスは固定にしておくとよい |
| 〃 | ファイアウォール | システム設定 → ネットワーク → ファイアウォール → オプション で Node を許可 |
| 「スケッチ読み取り」が使えない | APIキーか残高 | `pnpm --filter @zumen/server apikey` で理由が出る |
| 「○○さんが編集中です」 | 他の人が開いている | 空くまで待つ。急ぐなら「編集を引き継ぐ」 |
| ログインできない | IDかパスワード違い | `user:list` で確認。`user:passwd` で変更 |
| 「何度もまちがえたため…」と出る | 10回まちがえて止まった | 30分待つ。急ぐなら、管理用アカウントの「利用者の管理」→「ログインを解除」。<br>ターミナルなら `user:passwd` でパスワードを再設定すれば、すぐ入れる |
| 記録を見たい | — | `data/server.log`（自動起動のとき） |

## 毎月見ておくとよいこと

- **APIの使用額**：<https://platform.claude.com/usage>
- **控えが取れているか**：`BACKUP_DIR` に指定したフォルダを開いて、日付のフォルダが増えているか

## アプリを新しくする

アプリを直したときは、**`update-mac.command` をダブルクリックするだけ**。

やってくれること：

1. いまの `.env`（APIキー）と `data/`（案件のデータ）を、
   ホームフォルダ（Finderの左の家のマーク）の `zumen-更新前の控え > 日付` に控える
2. 最新の中身をダウンロードして入れ替える（`.env` と `data/` には触らない）
3. 必要な部品をそろえる
4. 自動起動を設定してあれば、サーバーを立ち上げ直してブラウザを開く

終わったら、ブラウザで **`command + shift + R`** を押して読み込み直すこと。
（押さないと、前の画面が残って新しくならないことがある）

> 自動起動を設定していない場合は、黒い画面で `control + C` を押して止めてから、
> `start-server.command` をダブルクリックする。

Windows は `update-windows.bat` をダブルクリックしたあと、
`start-server.bat` で立ち上げ直す。

### 手で入れ替えるとき

`update-mac.command` が使えないときは、次の順でやる。

1. サーバーを止める（`control + C`）
2. **`.env` と `data/` フォルダを、どこかに退避しておく**
3. 新しいZIPを展開して、古いフォルダと入れ替える
4. 退避した `.env` と `data/` を、新しいフォルダに戻す
5. `./test-mac.command` で動作確認
6. `./start-server.command` で起動

> `.env`（APIキー）と `data/`（案件のデータ）だけは、必ず引き継ぐこと。

## ログインの保護

- ログインは、**使わずに10日**たつと切れる。使っている間は延びていくので、開いたまま編集していれば切れない。
  使わないまま11日目になったら、入れ直してもらう
- **10回**まちがえると**30分**ログインできなくなる
- 5回目から「あと○回で止まります。管理者に確認してください」と出る
- 止まっている間は、画面に残り時間が出る
- **管理者がパスワードを変えれば、待たずにすぐ入れる**
  （「利用者の管理」→「パスワードを変える」、または「ログインを解除」）

## パスワードの決め方

社内のネットワークにいる人なら、誰でもログイン画面までは開けます
（中身はログインしないと見られません）。守っているのは実質パスワードだけなので、
次のようにしてください。

- **12文字以上**
- 会社名・年号・人名を**そのまま使わない**（`fujielex2026` のようなものは避ける）
- 他のサービスと**使い回さない**

**まちがえたときの動き**（実装と一致）：

| 回数 | 画面に出ること |
|---|---|
| 1〜4回目 | 「IDまたはパスワードが違います。」だけ |
| 5回目 | 「あと5回まちがえると30分間ログインできなくなります。管理者に確認してください。」 |
| 6〜9回目 | 同じ文言で、残り回数が減っていく |
| 10回目 | **30分間ログインできなくなる**（画面に残り時間のカウントダウンが出る） |

正しいパスワードで入れた時点で、この数は消えます。
30分待てないときは、**管理用アカウントの「利用者の管理」→「ログインを解除」**で
すぐ入れるようになります（パスワードの再設定でも解除されます）。

# 第4部　リポジトリを「非公開」にする

**第2部・第3部がぜんぶ終わって、他のパソコンから使えることを確かめてから**行う。

## 4-1. なぜやるのか

いまアプリのプログラムは GitHub に「公開」で置いてある。
URLを知っていれば誰でも中を見られる状態。

**APIキーもパスワードも入っていない**ので、見られて即困るものはない。
ただし手順書には社内の運用（サーバー役のMac、控えの置き場所など）が書いてあるので、
**社外に見せる必要がない以上、非公開にしておく**のが安全。

> 非公開にしても、アプリの動きは何も変わらない。
> 変わるのは「新しくするときの取ってき方」だけ（→ 4-4）。

## 4-2. 先に確かめること

次のどちらも「はい」になってから進む。

- [ ] サーバー役の Mac mini に、アプリのフォルダが**もう置いてある**
- [ ] 他のパソコンからブラウザで開けて、ログインできた（2-11 が終わっている）

> まだなら、先に第2部を終わらせること。
> 非公開にすると、ログインしていないパソコンからはダウンロードできなくなる。

## 4-3. 切り替える

1. ブラウザで <https://github.com/takayukiokushin/zumen> を開く
   （GitHubに**ログインした状態**で）
2. 画面の上のほうにある **「Settings」**（歯車のアイコン）を押す
3. いちばん下までスクロールする。
   赤い枠の **「Danger Zone」** という区画がある
4. その中の **「Change repository visibility」** の行にある
   **「Change visibility」** ボタンを押す
5. **「Make private」** を選んで **「I want to make this repository private」**
6. 確認のため、**`takayukiokushin/zumen`** と入力するよう求められる。
   画面に出ている文字をそのまま打つ
7. **「I understand, change repository visibility」** を押す

これで完了。リポジトリ名の横の表示が `Public` から **`Private`** に変わる。

> 画面が英語で分かりにくければ、赤い枠（Danger Zone）の中の
> **visibility（公開範囲）** という言葉だけ探せばよい。

## 4-4. 非公開にしたあと、アプリを新しくする方法

ターミナルからの直接ダウンロードは通らなくなる。
代わりに**ブラウザで落としてから**入れ替える。

1. 古い `zumen-*.zip` が「ダウンロード」フォルダに残っていたら**捨てる**
2. GitHubに**ログインした状態**で
   <https://github.com/takayukiokushin/zumen> を開く
3. 緑色の **「Code」** → **「Download ZIP」**
4. アプリのフォルダの **`update-mac.command` をダブルクリック**
5. ブラウザで **`command + shift + R`** を押して読み込み直す

> `update-mac.command` は、インターネットから直接取れないと分かると、
> 自動で**ダウンロードフォルダの `zumen-*.zip`** を探して使う。
> どのファイルを使ったかは画面に出るので、日付を見て確かめること。

## 4-5. もとに戻したいとき

同じ場所（Settings → Danger Zone → Change visibility）で
**「Make public」** を選べば公開に戻せる。何度でも切り替えられる。

## 4-6. 社内の誰かにも見せたいとき

非公開のまま、相手のGitHubアカウントだけに見せられる。

1. **Settings** → 左の **「Collaborators」**
2. **「Add people」** で相手のGitHubのIDかメールアドレスを入れる
3. 権限は **Read**（見るだけ）でよい
